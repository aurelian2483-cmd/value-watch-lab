# Hosted presence boundary — provider-neutral QA only

Based on PR #197 head 2ea902105185b072c3ef831ab042b6e5138e57a4; enrollment kit Windows/Linux and full research regression passed. This WSGI application reuses the accepted presence registry and accepts only PC cursor and heartbeat operations. It does not expose queue operations, observer data, revocation, arbitrary commands or GPU execution. No HTTP server is launched by the factory. The operator CLI supports explicit one-time provisioning, local status and local revocation. It reads role credential digests from configuration and prompts for raw credentials without echo when needed. The app startup requires a pre-existing private state directory and database; it does not create or repair missing state. Database identity is checked per request, and existing-only SQLite mode prohibits recreation if the file disappears. On POSIX, owner permissions and regular-file/single-link checks are required.

## Configuration contract

Use SKY_MODE=PRESENCE_ONLY_QA; SKY_APPROVED_HOST (exact approved DNS hostname); SKY_APPROVED_REVISION (40-character pinned revision); SKY_STATE_DIR (canonical private existing directory on durable local storage); four separate high-entropy token SHA-256 digests in SKY_OPERATOR_DIGEST, SKY_CPU_DIGEST, SKY_OBSERVER_DIGEST, SKY_PC_DIGEST. No default credentials, secrets in source, or public setup endpoint. The factory uses the server's trusted WSGI scheme and exact Host, never X-Forwarded headers directly. A production-grade serving adapter and trusted proxy must reject invalid framing, normalize approved authority, establish HTTPS reliably, prevent direct ingress bypass, enforce connection/request rate/size/time limits and redact credentials from logs. The supplied wsgiref TLS fixture is test-only and must never be publicly exposed.

Offline QA: PYTHONPATH=research/optional-pc-worker python -B -m unittest discover -s research/hosted-presence-boundary -p 'test_*.py' -v. Tests include actual local HTTPS, existing-only storage, restart, revocation, scope and role isolation, bad requests and database replacement. This is not a complete production ingress or durable cloud service. Filesystem checks assume trusted host administrators and a private directory; rollback to legitimately older state requires an external anchor and is not prevented here. Credential rotation, provider-specific reverse proxy/rate limits, cloud storage backup/restore, independent result intake, remote PC acceptance and GPU work are not authorized or implemented. No real provider credentials, deployment, merge, protected evaluation or scientific publication. Research UNVALIDATED; production dispatch and publication BLOCKED.
