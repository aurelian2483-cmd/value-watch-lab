# Cloudflare SQLite Durable Object presence pilot

Base: accepted PR #198 at 1afcddd2eb309cbb0f32ea9cb7cd991aba8c73d4; all four acceptance workflows passed. This separate Cloudflare adapter implements only the optional PC-presence protocol. The existing Python numerical engines, controller, site and production branches remain untouched.

The SQLite-backed Durable Object uses one fixed namespace identity and synchronous transactions for explicit provisioning, monotonic heartbeat sequence and time, persistent policy binding, observer status and revocation. No arbitrary job or result routes. Requests are authenticated before reaching the object and again at the object. Four distinct high-entropy role credential digests must be supplied out of band. Exact HTTPS host required in remote mode; local test mode only accepts an exact loopback HTTP address. Bounded body, restrictive JSON grammar matching the accepted PC client, no credential logs, no public health/status details. The observer and operator endpoints have separate credentials. Provisioning must be explicitly enabled, is one-time per database, and should be disabled immediately afterward. These are prototype security controls, not production network rate limiting or independent hardware attestation.

Wrangler configuration is disabled by default, has a deliberately separate local pilot name, disables workers.dev and previews, and uses a new_sqlite_classes migration. No cloud account, API token, secret or deployment is used by CI. The local runtime QA installs Wrangler 4.165.0 in a temporary directory, runs actual workerd with SQLite-backed Durable Objects, and tests concurrent replay, persistent state across process restarts, changed policy refusal, role isolation and durable revocation. Dependency installation is version-pinned at the Wrangler package level, not yet fully locked transitively. Logs are disposable. See https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/ and https://developers.cloudflare.com/durable-objects/reference/durable-objects-migrations/.

The user's existing Hello World Worker sky-research-controller.aurelian2483.workers.dev is not modified. The Cloudflare job queue, hosted CPU adapter, scheduling, result intake, actual PC connection and GPU dispatch are not implemented by this pilot. ## Phase 2 — fixed QA queue on Cloudflare

Baseline PR #199 at 5c1f8eca1fed398ef284ed859add29bed86f1fab passed local workerd acceptance (45588304436) and full regression (45588304415). This phase adds an independently provisioned one-shot fixed-QA queue inside the existing SQLite Durable Object. Its queue routes are available only in explicit LOCAL_PRESENCE_QA mode with SKY_QUEUE_ENABLED=true; even a correctly configured remote presence deployment cannot access them. The queue binds the exact approved revision, credential configuration and independently supplied plan digest for a bounded admission window. Admission is atomic and once only; missed windows do not catch up. Fixed CPU probe and local QA jobs can receive at most one active lease, while GPU stays blocked. Lease tokens are hashed in storage, stale leases are quarantined, and revocation survives restart. Duplicate receipt digests are rejected; a recorded digest is not authenticated numerical evidence. Observer status is stored state only; claim/submit/revoke reconcile expiry. The optional PC is not required or granted queue access. There is no arbitrary task submission, automatic retry, worker execution, remote scheduling, or result acceptance. The 2-second local test lease is only available in loopback QA mode; normal test leases are 240 seconds.

CI exercises original presence protocol plus actual workerd queue admission concurrency, lease races, restart, expiry, revocation, missed windows, policy mismatch and wrong-role denial. It uses temporary local storage and synthetic credentials only. No live Cloudflare change, paid plan, main merge, scientific validation or publication.
