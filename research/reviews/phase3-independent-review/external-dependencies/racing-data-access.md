## Evidence required from an authorised sample

1. Ask for a consecutive closed seven-day window as a diagnostic sample, with dates agreed once the supplier confirms it has the original versions. Use the already eligible source population and all scheduled races, including abandonments, voids and missing feeds. Ask for an independently documented correction example if none occurs in the sample. Neither retrospective sample enters the registered study.
2. Reconcile independently enumerated meetings, races and each declared field, per native IDs, with scratchings, dead heats, non-finishers and no-result states explicit. Request both original result and amendment ledger with release IDs, stable parent revision IDs, publication/receipt distinction, timezones and source-clock accuracy. Keep official placings, settlement and timing observations distinct.
3. Map the observer, adjudicator, upstream rights holder, distributor and transformation for each field. Retain a declaration or auditable data dictionary for editorial independence. Delivery through a separate API or website never establishes independence on its own. A separately operated start-time sensor can corroborate times only within its own coverage and uncertainty.
4. Attach rights for automated access, scientific computation, immutable raw versions/hashes, approved backups and locations, named reviewer access, permitted retention period and expiry, derived reporting, and disposal. Keep licensed bytes out of public Git and use an approved secure review channel. Ask whether an auditor can instead independently access identical versioned data from the provider under their own agreement.
5. Calculate completeness against the dated independent denominator and disclose every unresolved race, field, outage and mismatch. Keep incomplete, contradictory or unlicensed inputs out of the registered ledger. Prices are market comparisons. The registered protocol excludes paid accounts/services.
