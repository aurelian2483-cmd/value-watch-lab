# Research Supervisor — Phase 1

Separate stacked draft from green scientific compute commit 7c95c0bce1c428c0d9d24fd230f009304c289837. Reuses the existing registry supervisor and lifecycle reader; does not change them. Only inspect a dedicated, stable local registry. `node research/research-supervisor/supervisor.mjs <registry-directory>` returns aggregate lifecycle counts, stable incident identifiers, severity, recommended manual action and a store fingerprint. The adapter checks bounded, nonsymlink files, orphan lifecycle folders, checkpoint and terminal artifact bytes, event time ordering, long-running age and active synthetic-store locks. Unavailable counts remain null. Age is a review signal, not proof of a stalled job; fingerprints do not certify results. No automatic repair, resumption, source modification, model execution, protected data or production deployment. The CI workflow creates a disposable five-fixture synthetic registry using the existing laboratory and inspects it. Before/after checks are not atomic or hostile-filesystem isolation. Future stages: cross-report contract checks, incident history and static reporting, acceptance audit. No always-on service configured.

## Phase 2 — cross-report monitoring

`node research/research-supervisor/report-monitor.mjs <artifact-directory> <revision>` inspects fixed laboratory and scientific compute status summaries. It distinguishes missing evidence, inconsistent contracts and recorded failure from recorded synthetic passes; CPU and GPU are separate. Existing producer checks remain authoritative for underlying artifacts. CI generates actual disposable synthetic reports using the existing adapters and verifies the expected CPU pass / GPU missing combination. No GPU execution, protected data, automatic repair or live monitoring service. A missing GPU report is a review incident, not evidence of hardware failure. The CLI returns nonzero on a blocking inconsistency; review status remains visible in the report.
